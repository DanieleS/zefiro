## New

- **Client-side upscaling.** The stream can now arrive below the screen resolution and be scaled up on the GPU, with Bilinear, FSR 1.0 or Snapdragon GSR. Two new settings, *Client-side upscaling* and *Upscaling sharpness*, control it, and the time it adds shows in the performance overlay. It switches itself off and goes back to direct output when the GPU is too slow or errors, when the stream size changes, and for HDR, 10-bit and PyroWave streams. Based on work from RamazanKara/nightjar.
- **Adaptive bitrate reacts to queue delay.** The adaptive controller now measures the queue building up at the access point by comparing each frame's arrival with the host's capture time. A standing queue lowers the bitrate by 10% before packets are lost, and a small queue keeps it from probing up. Based on work from RamazanKara/nightjar.
- **Aim each frame at a vsync.** A new opt-in setting presents each decoded frame on a chosen display refresh instead of as soon as it is decoded, which can reduce judder at high refresh rates. It works with Balanced frame pacing, without client-side upscaling. Based on work from drunkitguy/artemis-apollo2.
- **Frame loss report.** At the end of a session of 20 s or more, if 8% or more of the video frames never arrived, a message tells you the percentage and suggests a bitrate to try. Based on work from drunkitguy/artemis-apollo2.
- **Text typed in one piece.** Text sent to the PC is now carried as UTF-8 on the keyboard channel, without racing against key presses sent at the same time. Text sent to a Sunshine host is also packed into denser packets.

## Fixes

- **Decoded-frame queue.** Replacing queued frames in the video decoder is now atomic, which avoids lost or stale frames and buffer leaks. Based on work from RamazanKara/nightjar.
- **Control stream.** Control messages are encrypted in place, without the fixed 256-byte buffer that limited them.

## Notes

- Adaptive bitrate needs a Vibepollo host; on a stock host nothing changes.
