## New

- **A new Material 3 interface.** The app has a new shell with adaptive navigation, a library home with a hero and shelves, a coverflow of your games, a search section, a Stats section and a compact grid of PC tiles that shows each host's status and game count. The old views are gone. It fits phones, tablets, handhelds and TV windows, and the stream stays alive and fitted when the window changes.
- **Game page.** A new page per game replaces the stats sheet and the achievements list, with play statistics, achievements and the actions for that game.
- **Stats.** The chart comes first, with a month drill-down, and it says what is not recorded. It fits short windows.
- **Settings.** Settings are now a section with search, grouped choices and pinned rows, and host settings live in the same place.
- **Ayn Thor bottom screen.** The companion panel is rebuilt as a strip with a stats grid, a remote page, the game page achievements, settings choices and pinned pages. While browsing it shows the focused PC's details and actions, and it follows the sheet's game and the settings live. After a stream the panel is handed back.
- **Phone stream panel.** A side panel replaces the floating stream button, and the in-game menu is driven by a single list of stream actions. A stream health HUD routes performance stats to the companion.
- **Gamepad hints.** While a gamepad is connected, on phones too, the app focuses with the d-pad first and shows button glyphs live: hint rows, glyphs inside buttons, B on dialogs' cancel buttons, on back arrows and at the end of the stream controls' back row, X on the host chip, and glyphs for the keys that step a segmented control. Without a pad, touch words are shown instead.
- **A launch screen that tells what is happening.** Starting a game shows a full-bleed art scene with the phase of the launch and the frame rate in full when there is room. Cancel really cancels: it stops a connection still starting and quits the game it started on the host. On the Ayn Thor, the bottom screen shows "This session" with its own Cancel while the game starts.
- **Games start in a virtual display by default.** A new default for the setting that launches games in a virtual display.
- **Captures carried out by the host.** On a Scirocco host, the in-game menu's screenshot, "save last 30 s" and recording entries are carried out by the PC itself, using the capture tool configured there, so every client uses the same tool. The entries are hidden when the host has captures off, and the menu falls back to this client's shortcuts if the host rejects the action. The *Capture tool* setting is ignored by a Scirocco host.
- **Client-side upscaling.** The stream can arrive below the screen resolution and be scaled up on the GPU, with Bilinear, FSR 1.0 or Snapdragon GSR. Two new settings, *Client-side upscaling* and *Upscaling sharpness*, control it, and the time it adds shows in the performance overlay. It switches itself off and goes back to direct output when the GPU is too slow or errors, when the stream size changes, and for HDR, 10-bit and PyroWave streams. Based on work from RamazanKara/nightjar.
- **Adaptive bitrate reacts to queue delay.** The adaptive controller measures the queue building up at the access point by comparing each frame's arrival with the host's capture time. A standing queue lowers the bitrate by 10% before packets are lost, and a small queue keeps it from probing up. Based on work from RamazanKara/nightjar.
- **Aim each frame at a vsync.** A new opt-in setting presents each decoded frame on a chosen display refresh instead of as soon as it is decoded, which can reduce judder at high refresh rates. It works with Balanced frame pacing, without client-side upscaling. Based on work from drunkitguy/artemis-apollo2.
- **Frame loss report.** At the end of a session of 20 s or more, if 8% or more of the video frames never arrived, a message tells you the percentage and suggests a bitrate to try. Based on work from drunkitguy/artemis-apollo2.
- **Text typed in one piece.** Text sent to the PC is carried as UTF-8 on the keyboard channel, without racing against key presses sent at the same time. Text sent to a Sunshine host is also packed into denser packets.

## Fixes

- **Dialogs and confirmations.** Cancelling a yes/no confirmation is its No, and No carries B; an activity closes only its own dialogs when it stops.
- **Library hero.** The running game's buttons stay inside its card.
- **Late stream screen.** A late stream screen no longer lands on the next launch.
- **Held sticks and triggers.** Held sticks and triggers are kept while the controls are open, and the host's text input and mouse emulation stay off while they are open.
- **Library kept through launches.** The library stays in place under a linked launch and through a monitor session.
- **Decoded-frame queue.** Replacing queued frames in the video decoder is atomic, which avoids lost or stale frames and buffer leaks. Based on work from RamazanKara/nightjar.
- **Control stream.** Control messages are encrypted in place, without the fixed 256-byte buffer that limited them.
- **Stream setup.** The RTSP parser that negotiates the stream with the host is rewritten to follow the specification more closely, so hosts with unusual replies connect more reliably.

## Notes

- Adaptive bitrate needs a Vibepollo host; on a stock host nothing changes.
- Host-side captures need a Scirocco host; on any other host the menu keeps using this client's shortcuts.
