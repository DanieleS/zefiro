## New

- **Hold Guide to open the stream menu.** Holding a controller's Guide button for the chosen time opens the stream menu without sending Guide to the PC; let go earlier and Guide goes out as a short tap. Pressing another button or a D-pad direction while Guide waits sends Guide first, so Steam chords such as Guide+RB keep working. The new setting offers Off, 0.5, 1, 1.5 and 2 s, and is Off by default. Based on work from RamazanKara/nightjar.
- **Rumble and motion sensors stop without focus.** When the stream window loses focus (notification shade, split screen, system menus) every rumble motor is silenced and the gyroscope and accelerometer are unregistered, with each gyro stilled at the host once. When focus returns, the host's latest rumble levels are replayed and the sensors are registered again after the usual settle delay. In picture-in-picture they stay off until it ends. Based on work from RamazanKara/nightjar.
- **Intra Refresh requested by the client.** The client can ask the host for Intra Refresh in the streaming protocol, as an alternative way to recover from lost frames on a host that supports it. A new "Intra Refresh" switch in the HDR and codec settings turns it on; it is Off by default, and hosts that don't know it ignore it.
- **Faster video reception.** Video UDP packets are now received in batches, which lowers the CPU cost of receiving the stream.
- **Controllers announced when the stream starts.** Every attached gamepad is reported to the host as soon as the connection starts, instead of on its first input, and gamepads plugged in mid-stream are announced right away. Touchpads, motion sensor nodes and remotes are skipped. Based on work from bradloh/moonlight-android.
- **Smoother motion controls.** Gyro and accelerometer readings from pads and from the device are now handled on their own thread instead of the main one, so a few hundred readings a second no longer compete with touch and drawing. Based on work from RamazanKara/nightjar.
- **Faster AES detection on ARM64.** The client now asks the kernel whether the CPU has AES instructions, falling back to the previous check, so the encryption choice is more reliable. Based on work from qiin2333/moonlight-vplus.

## Fixes

- **Faster video recovery.** After 8 lost frames in a row the stream asks the host for a new keyframe, instead of waiting for 120.
- **Sturdier video, network and loss handling.** The streaming core picks up fixes from the upstream moonlight-common-c covering video frame reassembly, the ENet control connection, packet-loss handling and sockets, for a stream that copes better with a flaky network.
- **Safer stream statistics.** The streaming core now uses C11 atomics and RTP statistics are counted without race conditions, so the numbers shown are more reliable.
- **Audio stalls no longer reopen the stream.** A short AAudio stall now drops a single buffer instead of reopening the stream; only a stopped or disconnected stream, or three stalled writes in a row, is reopened. Based on work from RamazanKara/nightjar.
- **Gyro stops cleanly.** A motion reading still queued when sensors are turned off can no longer arrive after the stationary report and leave the camera turning.
- **Key and button releases never lost.** A key or button release is no longer dropped when the input queue is full, so keys and buttons can't stay stuck down on the PC.
